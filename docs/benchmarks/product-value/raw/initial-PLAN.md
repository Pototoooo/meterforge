# MeterForge 产品价值实验方案

执行日期：2026-09-11

## 实验目标

把 MeterForge 的简历证据从“技术压测”扩展为：接入效率、计量可信度和运营排障效率。LoreLattice 是接入方；MeterForge 本身负责事件接收、去重、聚合和查询。LoreLattice 的钱包/支付宝不作为 MeterForge 支付指标。

## 四组实验

1. **接入效率**：LLM Token、ASR 秒数、BYOK/平台归属。记录首次有效事件时间、一次配置成功率、计量规则错误率和求助率。使用 6–8 名参与者，比较裸 API 文档与 SDK/示例配置。
2. **计量可信度**：回放唯一、重复、乱序、延迟、错误单位和跨租户事件。使用独立 oracle，对照计量准确率、重复抑制率、跨租户隔离率、对账差异率和可解释性。
3. **运营排障效率**：设计重复计量、事件延迟、归属错误、单位错误、价格版本不一致和下游不可用六个剧本。记录定位时间、根因正确率、修复闭环时间、证据完整率和误操作率。
4. **激活/付费体验**：在 LoreLattice 中比较“余额 + 业务作业消费”与技术明细页面。支付未正式开通前只测模拟 webhook，不写成真实收入；MeterForge 只报告用量事件质量。

## 建议验收门槛

| 主题 | 主要指标 | 建议门槛 |
|---|---|---:|
| 接入 | 首次配置成功率 | ≥80% |
| 计量 | 有效事件准确率 | ≥99.99% |
| 去重 | 重复事件抑制率 | 100% |
| 隔离 | 跨租户事件拦截率 | 100% |
| 可查询性 | 事件到聚合可见 P95 | ≤60 秒 |
| 排障 | 根因正确率 | ≥80% |
| 排障 | P95 首次定位时间 | ≤15 分钟 |
| 体验 | 计费理解正确率 | ≥85% |

这些是实验门槛，不是已取得结果。
